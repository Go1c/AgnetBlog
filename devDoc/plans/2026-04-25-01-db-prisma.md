# Database And Prisma Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Add the PostgreSQL and Prisma foundation for content indexes, policies, sync jobs, AI tokens, and audit logs.

**Architecture:** Prisma is the database access layer. The database stores derived state and control-plane records only; Markdown frontmatter in GitHub remains the source of truth for publish metadata.

**Tech Stack:** Prisma 7, PostgreSQL, TypeScript, Next.js App Router.

## Task 1: Prisma Scripts

Add scripts to `package.json`:

```json
{
  "db:generate": "prisma generate",
  "db:migrate": "prisma migrate dev",
  "db:push": "prisma db push",
  "db:studio": "prisma studio"
}
```

Run:

```powershell
npm.cmd run typecheck
```

Expected: pass.

## Task 2: Schema Models

Create `prisma/schema.prisma` with these models:

- `AdminUser`
- `DirectoryPolicy`
- `ContentItem`
- `ContentAsset`
- `DocsNavNode`
- `SyncJob`
- `AiToken`
- `AuditLog`

Required enum concepts:

- `ContentType`: `BLOG`, `DOCS`
- `Visibility`: `PRIVATE`, `PUBLIC`, `UNLISTED`
- `SyncTrigger`: `WEBHOOK`, `SCHEDULED`, `MANUAL`, `AI`
- `SyncStatus`: `QUEUED`, `RUNNING`, `SUCCESS`, `FAILED`, `PARTIAL`
- `ActorType`: `ADMIN`, `AI`, `SYSTEM`

Add indexes for content type, visibility, published state, source path, sync status, and audit target.

## Task 3: Prisma Client

Create `lib/db.ts` with a singleton Prisma client suitable for Next.js development reloads.

Requirements:

- Reuse the client in development.
- Export `db`.
- Do not connect during import beyond Prisma's normal lazy behavior.

## Task 4: Repositories

Create repository modules:

- `lib/db/content-repository.ts`
- `lib/db/sync-job-repository.ts`
- `lib/db/audit-log-repository.ts`

Keep them thin. They should wrap common queries but not contain parsing, GitHub, or auth logic.
